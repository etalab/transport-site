`transit_realtime/gtfs-realtime.pb.ex` is the compiled result of `gtfs-realtime.proto` via the Elixir protobuf compiler plugin. The plugin nests the output in a directory named after the proto package (`transit_realtime`).

Do not edit it by hand please!

## Why the test fails on Mondays

`test .proto file is up-to-date` (`test/transport/gtfs_rt_test.exs`) compares our `gtfs-realtime.proto` with the one on google/transit's master branch, comments included. It is tagged `ci_only_on_mondays`, so after any upstream change it fails on every PR whose CI runs on a Monday, whatever the PR changes. The fix is to regenerate the files (below) in a PR of its own.

A second test checks that `gtfs-realtime.pb.ex` was generated by the `protobuf` version in `mix.lock`. The installed `protoc-gen-elixir` escript doesn't follow `mix.lock` updates, so check its version first:

```sh
unzip -p ~/.asdf/installs/elixir/<elixir version>/.mix/escripts/protoc-gen-elixir '*/ebin/protobuf.app' | grep vsn
```

## How to regenerate the files

* [gtfs-realtime.proto source](https://raw.githubusercontent.com/google/transit/master/gtfs-realtime/proto/gtfs-realtime.proto)
* Check `mix.lock` and use the same `protobuf` version for `protoc-gen-elixir`.

On Mac:

```sh
brew install protobuf
mix escript.install hex protobuf <version from mix.lock> --force
asdf reshim elixir
```

On Fedora (with asdf):

```sh
sudo dnf install -y protobuf-compiler
mix escript.install hex protobuf <version from mix.lock> --force
asdf reshim elixir
```

Then:

```sh
curl -sL https://raw.githubusercontent.com/google/transit/master/gtfs-realtime/proto/gtfs-realtime.proto -o apps/transport/lib/transport/protobuf/gtfs-realtime.proto
cd apps/transport/lib/transport/protobuf
protoc --elixir_out=. gtfs-realtime.proto
```

Then run `mix format`, and the tests, Monday ones included:

```sh
mix cmd --app transport mix test test/transport/gtfs_rt_test.exs --include ci_only_on_mondays
```

A comment-only upstream change leaves `gtfs-realtime.pb.ex` unchanged.
